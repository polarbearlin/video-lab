# 3D 角色视频（先出歌 · Blender · 本地渲染）

这套流程是做《大肥鱼 · 自我介绍》（`demos/deepseek/v5`–`v13`）时一步步磨出来的。核心经验：**先有歌，再做画面**。之前先做画面、最后硬配乐，配乐怎么改都"不太有趣"；换成 Suno 的歌以后才对味。所以新片子一律从歌开始。

用户偏好（务必遵守）：
- 用大白话中文解释，别堆术语。
- 文案不能密：画面上的字约每 30 秒 70 字（每秒 4–5 字）。
- 要有趣的双向互动（角色 ↔ 主人 ↔ 网友），不要平铺直叙地讲知识。
- 动作要活泼：长抛物线快跳、滑行、骑物体、顶东西、被砸扁；镜头紧跟，有推有拉。
- 每轮都要**独立 Agent 审片打分**（见第 5 步）。
- 我写代码并推送；渲染交给用户本地 Mac 的 Agent（见 `references/local-render.md`）。

## 第 0 步：先提醒用户 —— 先出歌

接到新片子，第一件事是提醒用户："这次我们先把歌做出来：先一起打磨歌词，你拿去 Suno 生成，挑一版发我。"然后：

1. **定故事线和段落**：按片长（常见 60–90 秒）列出章节，每章一句话说清楚发生什么。
2. **写歌词**，规则（这些都是被用户纠正过的）：
   - 全程是**一个女生唱**（角色本人），用"你"称呼观众 / 主人。**别在歌里唱"主人"**，唱出来显得卑微、别扭。
   - 歌词**不用和屏幕上的台词一模一样**，反而别一样（眼睛读、耳朵听同一句会重复）。只保留 4–6 个"钩子词"，和对应画面同时出现。
   - **要可爱**：角色自称（如"本鲸"）、拟声词（噗噜噗噜、咕嘟、叮～）、句尾语气词（呀 / 啦 / 哦 / 耶）、叠词（圆滚滚、排排坐）、玩角色自己的梗（AI 就唱"服务器繁忙～请稍后再试哦"）。
   - 每段标注编曲提示（Suno 会读方括号）：`[Intro: music box, whisper]`、`[Break: one beat of silence]`、`(spoken)` 念白、`(whisper)` 悄悄话。
3. **写风格提示词**：模板和三个方向的对比见 `references/song-first.md`。默认推荐"kawaii future bass, 128 BPM"。
4. 用户在 Suno 里生成，挑一版发 mp3（文件在 `/root/.claude/uploads/...`）。我听不到声音，但能精确分析节拍和歌词时间；**好不好听只能用户判断**，要明说。

## 第 1 步：分析歌 → 得到"歌曲时间表"

```bash
pip install -q faster-whisper     # 不需要 PyTorch；环境能连 pypi 和 huggingface
```
- 节拍：`librosa.beat.beat_track(units='time')` → BPM 和每一拍的时间；看哪一拍是小节第一拍。
- 歌词时间：faster-whisper `medium`、`int8`、`word_timestamps=True`。
  - **坑 1**：它自带的音频解码（PyAV）版本冲突会报 `metadata_errors`，改成用 librosa 读成 16 kHz 数组再传进去。
  - **坑 2**：给了 `initial_prompt`（参考歌词）时，它会把参考歌词原样吐回来冒充识别结果。可疑的段落要单独切出来、不带 prompt 重跑。
  - 识别错字很正常（"服务器"→"夫妻"），只要时间对就行，和我们自己的歌词对照着用。
- 产出：一张表 —— 每段起止秒、每个钩子词在第几秒。**画面的 plan.py 就按这张表排时间**（先有歌，画面去对歌）。
- 如果是先有画面、后来才拿到歌（大肥鱼 v13 就是这样），就按拍子剪歌：剪掉 / 重复整小节，接缝 30 ms 等功率交叉淡化，做法见 `demos/deepseek/v13/song.py`。剪完要用 whisper 再识别一遍接缝附近，确认没切断歌词。

## 第 2 步：素材

- **3D 角色模型（必须由用户提供）**：GLB，例如 Tripo 生成的手办风模型，放 `assets/models/<名字>/`。拿到先检查：
  - 有骨骼的版本，骨骼和网格的尺寸、朝向常常对不上（大肥鱼的骨骼是 0.2 m，网格 1.1 m，导入还是倒的）。这种情况直接用**不带骨骼的刚体模型**，靠压扁、拉伸、旋转、跳跃来表演。
  - 记下授权和署名（CC BY-NC-SA 之类），片尾卡要写。
- **界面截图**：要细、要真实。复杂的界面让用户拿我写的提示词去 GPT 生成，放 `ref/screens/`；简单的用 PIL 或无头 Chrome 画（Chrome 小窗口有缩放 bug：大窗口渲染再裁）。
- **贴纸、去底**：用户要"抠干净，不要白底"。

## 第 3 步：总计划 plan.py（唯一的时间来源）

ui / scene / audio / compose 都只读 plan.py。里面包括：
- 时间点：章节、台词气泡、每个事件、每一跳 `HOPS`（落地秒、设备、u、v、选项）、镜头表 `CAM`（秒、看哪、偏移、视角）；
- `events()`：给音效卡点用。

画面规则：
- **中文字一律做成图片卡**（PNG 带透明），别用 Blender 3D 文字。NotoSansSC 是可变字体，做立体字会重影。真要立体大字，用静态字体 `assets/fonts/ZCOOLKuaiLe-Regular.ttf`。
- 台词气泡：角色的跟着头顶、面朝镜头；主人的话做成屏幕左上方的 2D 气泡（在合成时叠，不受景深影响）。
- 只看画面会让人"得猜"的信息（排名、股价、日期），合成时加 **MG 大事记卡**：日历牌 + 一句话 + 年份刻度尺上滑动的点（`demos/deepseek/v12/mg.py`）。

## 第 4 步：Blender 场景（EEVEE，逐帧算好再打关键帧）

参考 `demos/deepseek/v10/scene.py`、`v11/scene.py`、`v10/figure.py`。要点：
- **风格**：先暗场（聊天界面、贴纸），钻进传送门，白光一闪，进入明亮的白色"发布会舞台"；平板设备平放在台面上。
- **角色材质**：分区手办材质（`figure.py`），皮肤哑光加次表面散射、头发缎面、蕾丝有光泽、裙子哑光。
- **灯光**：主光和轮廓光用 SPOT，并做灯光链接，只照角色（`light_linking.receiver_collection`）。亮舞台上的屏幕材质 coat=0、spec=0，否则屏幕上会反射出大块亮斑。
- **跳跃**：`hop_pose` 负责起跳前蹲、空中拉伸前倾、可选转圈翻跟头、落地回弹；镜头用弹簧平滑紧跟。
- **坑**（都踩过）：
  - `transform_apply(scale=True)` 一定要写上 `location=False, rotation=False`，否则会把位置也应用掉，带关键帧的物体会偏一倍。
  - 复制物体要重置 `hide_render` 和位置。
  - 结束 Blender 用 `ps -eo pid,comm | awk '$2=="blender"{print $1}' | xargs -r kill`，**千万别用 `pkill -f` 匹配脚本名**，会把自己的 shell 也杀掉。
  - 渲染开 `use_overwrite=False`：已渲的帧会跳过，断了重跑即可；局部重渲就先删掉那段帧。

## 第 5 步：云端预览 + 独立审片（每轮必做）

- 云端 Blender：`/home/user/tools/blender-5.2.2-linux-x64/blender`。低清预览参数 `--stills <帧号…> --scale 25 --samples 8`，然后 `compose.py --sheet` 拼审片图。
- **独立审片**：开一个 general-purpose Agent，给它审片图路径、剧情摘要和 plan.py，让它：
  - 打总分和分项分：叙事清晰度、趣味互动、镜头构图、可读性、光影、风格一致性；
  - 列出最严重的 5 个问题，具体到秒和"把 X 移到 Y"这类改法；
  - 指出哪一帧会让观众看不懂。
- 按意见改完再出图复查。给用户看之前，自己也要打一个分。

## 第 6 步：交给本地 Agent 渲染（GitHub 联动）

完整流程和提示词模板见 **`references/local-render.md`**。简要说：每个版本写一个 `render.sh`（prep / stills / full / upload），推到 GitHub，给用户一段可以直接复制的提示词；本地 Agent 渲染后上传 Release；我用 `gh api` 下载下来审片。

## 第 7 步：合成

- `compose.py`：帧 → mp4。叠加层（章节大标题停 4 拍后缩到角落、底部导航）用 ffmpeg concat 做成透明视频再叠；白光转场用 lavfi 的白色画面加 fade。
- 分段渲染的片子用 `--join` 拼接；声音另外重新拼，避免接缝处淡入淡出。
- 歌曲版：歌是主体，叠一层轻音效（落地、弹出、唱片刮擦、笑声、鸟叫），音量压在歌下面。**有音高的音效（音阶、铃声、长号）一律去掉**，免得和歌跑调（`SFX_ONLY=1 python3 v12/audio.py`）。
- 最后一句唱不完就让片尾卡多停一会（`remix.py --hold 1.5`），别硬切。

## 安全和仓库规矩
- 视频、音频、字体、`build/` 都不进 git。
- API Key 不让用户贴进聊天，放到环境设置的 Network secrets。
- 给本地 Agent 的提示词里必须有："不要上传任何密码、密钥、账号信息"。
- commit / PR 里不写模型名。
