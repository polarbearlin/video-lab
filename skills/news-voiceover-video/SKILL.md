# 时事新闻口播

把《黄仁勋复职的十一天》（视频号，竖屏 5:28）整套做法沉淀下来。核心：**用户把关文案和声音，Grokbot 找素材，Claude 剪辑配乐出片**，三方在 GitHub PR 上接力。

## 谁做什么

| 角色 | 负责 |
|---|---|
| 用户（Vasanti） | 给选题；在 **Gemini** 优化文案；用**豆包克隆音色**录配音；需要时提供 **Suno** 曲子（电脑里有下载好的）；看成片、拍板 |
| Grokbot | 在 PR 上按任务单找新闻视频、截图、行情数据，免费出示意插画，登记来源表 |
| Claude（你） | 写文案 v1、配音脚本、任务单；开 PR 和监听；验收素材；配音对齐；剪辑、配乐、混音、渲染；审片；发布文案 |

仓库：`polarbearlin/video-lab`（**公开仓库**），项目放 `demos/<英文短名>/`，分支 `collab/<英文短名>`。频道：北极熊吃海豹（口号“看热闹，也看门道。”）。

## 流程总览（顺序不要乱）

| 步 | 你做 | **要用户提供 / 做的事**（到这一步就明确说出来） | 细节 |
|---|---|---|---|
| 0 开工 | 问清选题、时长、版式 | 热点是哪条、手上的链接或资料 | `references/script.md` |
| 1 文案 v1 | 快速找料，写 v1（含画面设想、标题备选） | **拿纯净版去 Gemini 优化，把优化后的全文发回来**（附可直接粘贴的 Gemini 提示词） | `references/script.md` |
| 2 定稿 | 收下用户发回的版本当定稿，只列提醒不擅自改 | — | `references/script.md` |
| 3 配音脚本 | 出豆包配音脚本（分份、汉字数字、接原声只说引子） | **按份粘贴进豆包录音，每份导出一个音频发回来** | `references/doubao-voice.md` |
| 4 开 PR | 和第 3 步同一轮做：建分支、放定稿和任务单、开 PR、发【素材任务】 | **去让 Grokbot 打开这个 PR 的监听** | `references/grokbot-pr.md` |
| 5 协作找料 | 订阅 PR + 后台轮询；每批交付验收、回【Claude】留言、补缺口；插画先样张后批量 | 偶尔拍板（新闻片段用不用、风格样张） | `references/grokbot-pr.md` |
| 6 配音回来 | 识别、逐句对齐、量语速，慢了就 1.2 倍变速 | 念错漏句时**单独补录那一句** | `references/doubao-voice.md` |
| 7 剪辑 | 外框、逐句镜头表、原声插入、字幕、渲染 | — | `references/production.md` |
| 8 配乐 | 先查曲库；按文案分段设计 cue、停乐、音效；混音验证 | **需要时发 Suno 曲子**（或照提示词生成两版） | `references/music.md` |
| 9 审片交付 | 联系表自查、独立审片、发成片；用户说定稿后给视频号文案；PR 收尾 | **看成片、提修改** | `references/qa-delivery.md` |

步骤 3 和 4 是同一轮：拿到定稿后，先把配音脚本发给用户去录，紧接着开 PR，让 Grokbot 在用户录音的同时找素材。素材和配音两条线并行，汇合在第 6–7 步。

## 每一步结束时怎么跟用户说

用户希望你**主动引导**：每次交付都以“下一步需要你做什么”收尾，一两句说清楚，不要让用户猜。例：

- 文案 v1 后：“下一步请拿纯净版去 Gemini 优化，优化后的全文发回给我。下面这段可以直接粘给 Gemini：……”
- 配音脚本后：“一共 3 份，按份粘进豆包录，每份导出一个音频发我。我这就去开 PR 让 Grokbot 找素材。”
- 开 PR 后：“PR 开好了：<链接>。请让 Grokbot 打开这个 PR 的监听。我这边也在监听。”
- 要配乐时：“配乐这步到了。你电脑里之前生成的 Suno 曲子可以直接发我；想要新的，我给你提示词。”
- 成片后：“这一版改了什么、片长、响度。看完告诉我哪里要改。”

## 用户的偏好和口径（这几条是一路踩出来的，照做）

- **少核查、多做片**：用户不要逐条事实核查和多轮评分。只在指控类说法、对不上的数字、找不到出处的引语时提醒一句。
- **不要道德洁癖**：新闻台片段该引用就引用，普通人截屏就截屏。
- **仍然守住**：AI 图不冒充实拍（插画标“示意图”，网友 AI 梗标“网友 AI 梗”）；指控类说法保留“有理由认为 / 据报道”并写上对方否认；不点名与事件无关的私人；不画真人面孔；X 截图里普通网友打码。
- **花钱要先问**：即梦配音 / 生图要积分，先报价等确认。插画交给 Grokbot（免费）。
- **配音以实际录音为准**：用户念得和稿子不一样没关系，字幕跟着配音走。
- **配乐要跟着文案变、但不能碎**：一首统一风格的长曲按段落换情绪，按小节剪；停乐、上升音、重击做“变化”。
- **用户对 token 敏感**：子代理最多开一个（独立审片）；能缓存的渲染只重渲改动部分。
- **渲染好了就直接发**（SendUserFile），默认只出竖屏，横屏按需。
- 用户的克隆配音**不进公开仓库**；Suno 曲子用户同意进仓库曲库；Mixkit 只放下载脚本。
- 不推 main、不合并 PR、不发布；提交信息和 PR 里不写模型名。

## 踩过的坑（速查）

- 被拦的新闻站换转载站，不硬绕。行情要等收盘再取，盘中价只当草稿。
- 推送被拒：Grokbot 先推了，`git pull --rebase`。`*.mp4/*.mp3` 被忽略，要入库的用 `git add -f`。
- 监听后台任务 2 小时会被停、容器重启也会停：处理完每次都重起，被停了告诉用户。
- 插原声的剪接点放在两句之间静音的中点，不然会切掉字。
- 数字多的句子对齐率低：识别结果先把阿拉伯数字换成汉字读法再对齐（脚本已处理）。
- 整页截图缩小后读不了：加大号引语或换视频；暗色截图直接换掉。标签放画面顶部，别挡新闻台字条。
- 涨跌柱标签要带正负号、红涨绿跌、不出画；片尾署名分行、写这一版真正用的配乐。
- 免费空镜里可能有可读的无关新闻标题，验收时放大看。
- 曲子前奏很长时入点要按能量曲线往后放；停乐效果用纯配乐渲染验证。
- 不加限制器时 AAC 编码后真峰值会冲到 −0.2 dBTP，`score.py` 已内置 alimiter 0.708。
- Suno 只能一次出一首；结构标签不是歌词，要跟用户讲清楚，不然用户会以为会被唱出来。
