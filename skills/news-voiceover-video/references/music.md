# 第 7 步：配乐、音效与混音

## 用户对配乐的要求（原话整理）

- 要像自媒体那种配乐：**跟着文案走，有变化，变化要舒服，能抓眼球**。一首垫底从头放到尾不行。
- 但也不能“太粉碎”：7 首不同的曲子硬切，听着散。最后的解法是**一首风格统一、按段落换情绪的长曲，按小节剪开对到画面上**。

## 配乐从哪来（按顺序）

1. **曲库里现成的 Suno 曲子**（首选，可重复用）。仓库分支 `news-voiceover-kit` 的 `music-library/`：
   ```sh
   git fetch origin news-voiceover-kit && git checkout origin/news-voiceover-kit -- music-library
   cat music-library/曲库说明.md        # 每首的段落、情绪、适合什么题材
   ```
   曲库里有 `bars.json`（小节线和每 4 小节的能量），可以直接按小节剪。
2. **让用户提供**：用户电脑里存着自己用 Suno 生成过的曲子。需要配乐时直接问：
   > 配乐这步到了。你电脑里之前用 Suno 生成的那几首（比如《黄仁勋》用的 JH_full_score 两版）可以直接发我；如果想要这次题材专属的，我给你一份 Suno 提示词，你生成两版发我。
   收到新曲子：跑 `music_bars.py` 分析、写进曲库说明，`git add -f` 加进 `music-library/suno/`（用户同意过上传仓库，方便以后调用）。
3. **新写 Suno 提示词**：模板 `assets/templates/Suno单曲提示词.md`，按本片段落改情绪。
4. **Mixkit 免费曲库**（不需要用户提供时的兜底）：`bash scripts/fetch_mixkit.sh 素材/audio` 下载 7 首配乐 + 14 个音效（《黄仁勋》修订 v2 用的就是这套）。Mixkit 授权不允许单独再分发，所以只放下载脚本、不传 mp3 进公开仓库。

## Suno 怎么写（用户不熟 Suno，要讲清楚）

- Suno **一次只生成一首**。所以写成**一首完整纯音乐**，按片子段落顺序换情绪，不要分 7 首。
- 全曲**固定一个速度和调**（如 100 BPM、D 小调，轻松段转关系大调），只换曲风和配器。速度不变，才能按小节剪开、段落对位不乱拍。
- Custom 模式；Title / Style / Exclude Styles 照抄；歌词框里**只放方括号的结构标签**。
- **一定要跟用户解释结构标签**（用户问过“歌词会唱出来吗”）：方括号里是给 Suno 看的段落说明，不是歌词，不会被唱出来；整首没有一句歌词。万一出现人声，打开 Instrumental 再生成。
- 生成不到目标时长就用 Extend 从结尾续写。每次出两版，两版都发来（两版的段落不同，剪的时候可以混用）。
- 商用要用 Suno 付费账号生成，发布文案里提醒一句。

## 配乐跟着文案走（cue sheet）

先把片子分成 6–8 个段落，每段定一个情绪，再从曲子里挑能量合适的块：

| 段落 | 情绪 | 选块依据（`music_bars.py` 的输出） |
|---|---|---|
| 钩子 | 暗色鼓点、满编、紧张 | 响度高、打击乐比例高 |
| 起因 / 调查 | 脉冲、神秘、鼓轻 | 低频中等、亮度低 |
| 转折 / 压力 | 钢琴动机、克制 | 中等 |
| 高潮 / 幕后 | 先蓄力再持续推进 | 能量逐块上升的连续几块 |
| 狂欢 / 玩梗 | 放克、轻快 | 亮度最高、打击乐最密 |
| 质疑 | 一下转冷、稀疏、没鼓 | 响度低、打击乐低 |
| 结尾 | 钢琴收尾，停在长音 | 曲子的自然结尾，`align='end'` 对齐片尾 |

**剪法**（`score.build_mix` 的 cues）：每段 `segments=[(文件, 起, 止), …]`，起止吸附到最近的小节线（0.4 秒内）；不够长就再接同一首的另一段，60 ms 交叉淡化；段落交界在小节线上切换。

## 让配乐“有变化”的设计：默认纯配乐，不加音效

《黄仁勋》修订 v3 加了打字机、故障声、嗖声、重击、心跳等 18 处音效，用户听完的反馈是：“有一些很尖锐、很奇怪的音效，听着就很不舒服，你还不如纯配乐呢。”从修订 v4 起**默认不加任何音效**，变化全部交给音乐本身：

- **换段**：段落切换落在小节线上，新段 0.15 秒淡入、旧段 0.8 秒淡出（`full.py` 里 `SFX_ON=False` 时自动这样设）。同一首曲子同一个速度，换段本身就是“变化”。
- **柔和让位**（取代硬停乐）：金句、当事人原话、原声前，配乐用余弦曲线在 0.3–0.45 秒内降到 0.15–0.3，说完 0.7–1.0 秒慢慢回来。drops 写成 `(起, 止, 增益, 渐弱秒, 渐强秒)`。不要降到 0、不要 60 毫秒的快切，那样听起来也像“咔”的一下。
- **片尾**：最后一句前慢慢让到 0.3，曲子自然收在钢琴长音上。
- 冷开场的新闻原声、当事人原声不算音效，照常保留。

只有用户明确要音效时才加（`JH_SFX=1` 打开旧设计）。加的话：只用低频、圆润的（低沉的 boom、柔和的 swell），避开高频和故障类（打字机、glitch、嗖声、电视转场）；不要同一种音效重复十几次；按响度而不是按峰值归一，整体比配乐低。

## 混音参数（`score.py` 已内置）

- 人声：旁白 −16 LUFS（高通 70 Hz + 轻压缩），原声 −17.5 LUFS；每段两端 12 ms 淡入淡出防咔哒。
- 配乐：每段按 −24 LUFS 归一再加 level（钩子 −7、狂欢 −6、其余 −8、结尾 −9）。
- 闪避：人声出来配乐压 7 dB（起 60 ms、回 600 ms，平滑包络），不是一刀切。
- 总线：整体归一到 −14 LUFS，`alimiter limit=0.708`，编码 AAC 后真峰值约 −2.6 dBTP（之前不加限制器时 AAC 后到了 −0.2，超标）。

## 混完要验证（别只听带人声的成片）

1. **纯配乐渲染**：把 build_mix 的 speech 和 sfx 置空再混一遍，逐段确认七段都有音乐、停乐处真的是静音（约 −140 dB）、前后 3 秒有音乐。低频能量检查会被音效干扰，一定要用纯配乐版：

```python
import full as Fu, score
T = Fu.build_timeline(); Fu.TL.extend(T)
orig = score.build_mix
score.build_mix = lambda p, total, speech, cues, drops, sfx, **kw: orig(p, total, [], cues, drops, [], **kw)
Fu.build_audio('/tmp/music_only.wav')   # 再用 librosa 量每个停乐段和前后 3 秒的 RMS
```
2. **响度**：`ffmpeg -i 成片.mp4 -af ebur128=peak=true -f null -`，目标 −14 LUFS 左右、真峰值 ≤ −1 dBTP。
3. 有前奏很长的曲子（Mixkit Thunder 前 20 秒几乎没鼓）：入点要按能量曲线往后放，不能从 0 秒开始。
