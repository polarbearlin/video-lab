# 第 4–5 步：在 GitHub PR 上和 Grokbot 合作找素材

## Grokbot 是谁、擅长什么

- 用户的另一个代理（Grok Bot），在 PR 里留言以 `【Grok Bot】` 开头，账号显示为 `cursor[bot]` 或用户本人。
- 擅长：下载新闻台视频片段（YouTube、新闻网站）、X / Truth Social 原帖截图、网页截图、行情数据，**生图免费**（用用户订阅的 ChatGPT 网页版）。云端容器下不了的（YouTube 机器人验证、X 登录墙）交给它。
- 它也会开监听，看到 PR 有新提交、新留言就干活。**它的监听要用户去开**，你开 PR 后要提醒用户。

分工：Grokbot 找素材、出插画、整理来源表；你写任务单、验收、剪辑、配乐、渲染。

## 开 PR（拿到定稿文案后立刻做，和用户录音同时进行）

仓库 `polarbearlin/video-lab` 是**公开仓库**。规矩：不推 main、不合并 PR、不放密钥和隐私信息、不提交用户的配音。

```sh
cd <仓库> && git fetch origin main
git switch -c collab/<项目> origin/main
mkdir -p demos/<项目>/{versions/v1,素材/{video,img,illus,x,data,audio},参考,配音,film}
# 放入：versions/v1/自媒体文案_v1.md、自媒体文案_v2_定稿.md、<片名>_豆包配音脚本_v1.md、
#       素材任务单_v1.md、插画任务单_v1.md（模板见 assets/templates/）、素材/来源表.md（只有表头）
git add demos/<项目> && git commit -m "<片名>：定稿文案、配音脚本、素材任务单" && git push -u origin collab/<项目>
gh pr create --draft --base main --head collab/<项目> --title "<片名>：素材协作（Grokbot × Claude）" --body-file <PR说明.md>
```

PR 说明照 `assets/templates/PR开场留言.md` 的「PR 说明」写；建好后马上发第一条任务留言（同一模板的「素材任务」）。
推送被拒（Grokbot 先推了）：`git pull --rebase` 再推。`*.mp4`、`*.mp3` 在 .gitignore 里，要入库的素材用 `git add -f`，配音永远不 `-f`。

**然后告诉用户**（回复里写清楚；用户一般已经提前开好了 Grokbot 的监听，说过“他已经开了监听”就不要再催）：

> PR 开好了：<链接>。请让 Grokbot 打开这个 PR 的监听，开始按任务单找素材。我这边也开了监听，它一交付我就验收。

## 你这边的监听（两层都开）

1. **PR 订阅**（实时推送评论、审核）：`subscribe_pr_activity(owner, repo, pullNumber)`。
2. **轮询兜底**（新提交、漏掉的评论）：用 Bash 后台跑
   `bash scripts/pr_watch.sh polarbearlin/video-lab <PR号>`，`run_in_background: true`，`timeout: 7200000`。
   - 每 60 秒查一次；Grokbot 一批推好几次，等这一批停 3 分钟再唤醒你；自己的提交和留言不算。
   - 它退出 = 有新东西，你会被唤醒。处理完**立刻重新起一个**。
   - 后台任务最长 2 小时会被停、容器重启也会停：被停了就重起，并告诉用户一声。

## 每次被唤醒怎么处理

1. `git pull --rebase`，看新文件和 `素材/来源表.md`。
2. 验收：视频用 ffprobe 看分辨率、时长、有没有声音；图片打开看（截图字是否清楚、是否需要打码）；插画看风格是否统一。
3. 回一条 `【Claude】` 留言，固定三段：
   - **已核对**：哪些能用、怎么用（例：“V23 竖拍，剪辑时两侧做模糊填充”）。
   - **缺口换个找法**：找不到的给**具体的替代找法**，不要只说“再找找”。常用替代：新闻台报道里插的同一画面（演讲、总部外景常在新闻里出现）、同一人物别的场合、Wikimedia Commons、Pexels / Pixabay / Mixkit 的免费空镜。相似就行，在来源表写“相似替代 Vxx：原因”。
   - **接下来**：下一批编号和优先顺序。
4. 有急事（某句旁白要不要删、收盘价是涨是跌）单独发 `【急事】`，让它马上回。
5. 重新起监听。

留言都以 `【Claude】` 开头，末尾带 “🤖 Generated with [Claude Code]” 那行（监听脚本靠它识别自己的留言）。

## 任务单怎么写

### 素材任务单（视频为主）——模板 `assets/templates/素材任务单.md`

- 编号：`V` 视频、`J` 截图 / 数据、`I` 插画、`A` 音频。文件名以编号开头：`V05_pbs_hq_endeavor_voyager.mp4`。
- 按文案段落分表，每行：要什么 / 用在哪句 / 去哪找、搜索词。数量写“至少 / 最好”，够用就行。
- 规格：mp4，1080p 优先、最低 720p，保留原声，前后各多留 2 秒；> 50 MB 放草稿 Release；每个文件登记来源表一行：`| 文件名 | 编号 | 内容 | 来源 URL | 原片起止 | 发布日期 | 分辨率 | 授权/引用说明 | 备注（相似替代）|`。
- 交付格式：每批推送后留言 `【交付】V01 V02 …；视频 N 段，截图 N 张；来源表已更新`，找不到写“未找到 + 原因”。
- 分三批：第一批是钩子和冷开场要的（新闻主播原声 3–8 秒至少两台、事件高潮画面、行情数据），第二批其余视频，第三批截图。
- **用户已定的口径**：新闻台片段（CNBC、ABC、NBC、PBS、福克斯、彭博、CNN）该引用就引用；普通人截屏就截屏；找不到原件找相似的也行。不要有道德洁癖。
- 仍然不收：AI 图冒充实拍；未确认的敏感素材；与事件无关的私人照片和信息。X 截图里的普通网友头像和名字打码；网友的 AI 梗图只能标“网友 AI 梗”。

### 插画任务单——模板 `assets/templates/插画任务单.md`

- 插画只做示意（剪辑时角落标“示意图”），约占画面 15%，10–12 张。
- **统一风格描述**中英文各一份，每张都加在提示词后面；画面里不出现可辨认的真人面孔、文字、标志，不出现性暗示。
- 16:9，2560×1440 优先，每张 2 个变体，`素材/illus/I01_a.png`；来源表登记工具、模型、完整提示词。
- **先出一张风格样张**，你确认后再批量。确认时给具体的调色意见，例：“黑色占七成以上，绿色只出现在光束、边缘光和小面积高光上，红色只做点缀”。
- 用户口径：插画交给 Grokbot（免费）；不要给插画加颗粒。即梦生图要花积分，只在用户要求时用，先报价。

## 收尾（成片交付、用户说完成以后）

- 留一条 `【Claude】收尾` 留言：成片已交付、哪些素材最终用了、感谢。
- `unsubscribe_pr_activity`，停掉后台监听。
- 代码和 json 提交到 PR 分支；PR 保持草稿、不合并（要不要合并由用户决定）。

## 踩过的坑

- **【急事】用来核原文**：文案里拿不准的数字、引语、报道措辞，放进第一条留言的【急事】，让 Grokbot 先把原文 / 截图找回来（《Anthropic》：奥特曼那句的出处和原话、Axios 原文措辞、盘中最低价）。结论回来以后再跟用户说要不要改，别先下判断。
- 用户取消的素材（“用相似视频代替，不用让 Grokbot 找了”）要马上在 PR 留言告诉 Grokbot，免得它继续找。
- 文案删减后，单独发一条【更新】：哪些编号不用找了、哪些重点变了。
- 素材全部交齐后后台轮询可以不再重起（PR 订阅还在，留言照样会推送）。

- 推送被拒：Grokbot 刚推过，`git pull --rebase` 再推。
- 以为音频在仓库里，其实 `*.mp3` 被忽略、提交时报错：要入库的（Suno 曲子）用 `git add -f`，配音不入库。
- 全页截图缩小后字看不清：任务单里要求**同时交整页和裁切后的关键段落**（`J24_abc_holding.png` + `J24_abc_holding_crop.png`）。
- 免费素材站的空镜里可能有可读的无关新闻标题（《黄仁勋》V06 报纸上有拜登头条）：验收时放大看，换掉。
- 行情数据要等收盘（美东 16:00）后再取，盘中价只能当草稿。
