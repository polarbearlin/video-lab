# 第 1–2 步：文案 v1 → 用户去 Gemini 优化 → 收回定稿

## 开工先问清楚（一次问完，有默认值的直接用默认）

| 问什么 | 默认 |
|---|---|
| 选题：哪条热点？手上有没有链接、截图、文章？ | 无（必须给） |
| 时长 | 4–5 分钟，不超过 300 秒（视频号）；抖音另出 1.5–3 分钟短版 |
| 版式 | 竖屏外框 + 16:9 画面窗（视频号主推）；横屏按需 |
| 频道名 / 口号 | 北极熊吃海豹 ·「看热闹，也看门道。」 |
| 对标视频 | 沿用《黄仁勋》的参考（脑袋开瓶器风格）；有新的就让 Grokbot 传到 PR 的 `参考/` 里 |
| 仓库 | `polarbearlin/video-lab`（公开仓库），项目目录 `demos/<英文短名>/` |

用户不需要你做逐条事实核查（原话：“我不太需要你去核查一些逻辑的正确性，我只需要你做视频”）。花时间在**把故事讲好、把片子做好**上；只在下面三种情况停下来提醒：说法会构成指控（间谍、犯罪）、数字明显对不上、引语找不到出处。

## 找料（快，够写稿就行）

- 先搜当天和前几天的报道，按时间线排出 5–8 个节点：起因、升级、转折、高潮、反应、未解问题。
- 被拦的站点换转载：纽约时报 → Inquirer 等转载；路透 → Investing.com；美联社 → PBS / Yahoo；Snopes → Yahoo 转载。被拦了不要硬绕。
- 记下每个关键事实的来源链接，写进文案末尾的「来源」表。这张表后面直接变成给 Grokbot 的素材任务单。
- 盘中的股价、还在变的数字，标【制作前复核】。

## 文案 v1 怎么写

**结构**（5 分钟片，照《黄仁勋复职的十一天》）：

| 段落 | 时长 | 写法 |
|---|---|---|
| 钩子 | 20–30 秒 | 用结果开场的反差（“六天前把话说死……一个周末过去全票反转”）→ 一个数字 → 一句当事人原话 → 一个问句（“这十一天到底发生了什么？”） |
| 第一幕 · 起因 | 50–60 秒 | 直接讲事件，不铺背景；关键原话单独成句（“我对妻子不忠。没有借口。”） |
| 第二幕 · 升级 / 转折 | 60–80 秒 | 时间顺序，每个节点一个日期、一个动作、一个数字 |
| 第三幕 · 高潮 | 60–75 秒 | 幕后推手、关键电话、反转；“改变一切的周末来了”这种段落钩子 |
| 第四幕 · 反应 | 40–60 秒 | 先狂欢（股价、网友梗、名人原帖），再“但掌声之外”转冷（质疑方） |
| 结尾 | 30–45 秒 | “到底谁赢了？”→ 三个各赢了什么 → 两三个还没答案的问题 → 一句短金句（“人回来了。但故事，还远没结束。”）+ 评论区提问 |

**写法**
- 口播按每分钟约 270 字估：5 分钟约 1300–1400 字（不含标注）。《黄仁勋》定稿 1436 字，1.2 倍速后成片 5:28。
- 短句为主，长短交替；每 30 秒给一个新信息、新反转或问句。
- 原话只留 4–5 句最有分量的，用引号；人名、机构译名全片统一。
- 指控类说法保留限定词（“有理由认为”“据报道”），对方否认要同时写上。不点名无关的私人（例：第二段关系对象）。
- 每段后面用 `> 画面：……` 写一行画面设想，方便后面拆素材任务单。
- 标记：【可删】尺度由用户定；【制作前复核】出片前再对一次的数字。
- 文件开头给 3 个标题备选。

**交付**：存成 `demos/<项目>/versions/v1/自媒体文案_v1.md`（已有 PR 分支就放分支里，还没开就先放本地），用 SendUserFile（attach）发给用户，同时在回复里贴一份**纯净版**（去掉 `> 画面` 和标注），方便直接复制。

## 交出 v1 时，必须提醒用户去 Gemini 优化

回复结尾固定带上这一段（把方括号里的换掉）：

> **下一步：请把纯净版拿到 Gemini 优化一版，再把优化后的全文发回给我。** 可以直接把下面这段连同文案一起发给 Gemini：
>
> ```
> 你是中文时政 / 科技自媒体口播的资深编辑。下面是一篇约 [5] 分钟的视频号口播文案，请帮我优化成更抓人的版本：
> 1. 钩子更狠：前 3 句就把反差和悬念抛出来。
> 2. 更口语、更有节奏：短句为主，长短交替，像对镜头讲给朋友听，不要播音腔和书面语。
> 3. 每 30 秒左右给一个新信息、反转或设问，不要有拖沓的背景段。
> 4. 不新增原文没有的事实、数字和引语；引号里的原话保持原样；“有理由认为”“据报道”这类限定词保留。
> 5. 保留分段小标题；总字数控制在 [1300–1450] 字。
> 直接输出优化后的全文。
> ```
>
> 你也可以自己在 Gemini 的版本上再改。发回来以后我按它出豆包配音脚本。

## 收回优化稿以后

**第一件事：数字数。** 汉字约 263 字 = 成片 1 分钟（含冷开场、原声和片尾，按用户上两期的实际语速）。定稿里标的时间码不可信（《Anthropic》定稿标 5:05，实际 2080 字 ≈ 8 分钟），对不上就在交付配音脚本时放在提醒的第一条，给出“删到多少字对应多长”。

**用户要删时：只删不改写。** 用户说“删到 5:30 左右”：按目标字数整句、整段地删，留下的字句和定稿一字不差，只为接上调标点；删完用脚本核一遍“删减稿的汉字是定稿的子序列”，并在删减稿开头写明删到多少字、预计多长。优先删：重复的铺垫、和主线弱相关的支线（《Anthropic》删了 Open Claw、独立评估机构、“温情面纱”）、还没核实的细节。删减稿另存 `自媒体文案_v3_删减版.md`，配音脚本跟着出 v2。

- **以用户发回的版本为准**，存成 `自媒体文案_v2_定稿.md`（文件头写“由用户改定，日期”）。不要再按自己的口味改回去。
- 快速比对一遍 v1，只挑这几类问题**列成提醒**，不擅自改：新出现的事实性说法和原报道不一致（“当面问”其实是“打电话问”）、语气比原话更重（“绝不”vs 原话“不打算”）、字数超出时长（给出要删多少字或读快到多少字/分钟）。
- 提醒写进配音脚本的「交付说明」里，用户录之前自己决定改不改。
- 然后直接进第 3 步出豆包配音脚本，同一条回复里交付（见 `doubao-voice.md`）。
