# 第 8 步：审片、交付、视频号文案

## 交付前自查（每一版都做）

1. **逐镜头联系表**：每个镜头抽 3 帧拼成一张图，一屏看完全片，挑这些问题：
   ```sh
   ffmpeg -i 成片_竖屏.mp4 -vf "fps=1/2,scale=270:-1,tile=8x6" -frames:v 1 sheet_%02d.png
   ```
   - 截图卡的字在手机上能不能读（读不了就加引语或换视频）。
   - 标签、日期章、来源角标有没有挡住新闻台字条或互相重叠。
   - 素材里有没有不相干的可读文字（别的新闻标题、普通网友的名字）。
   - 示意插画都标了“示意图”；AI 梗标“网友 AI 梗”。
   - 数据图的数字、符号、颜色对不对（红涨绿跌、`+31.5%`）。
   - 片尾署名有没有溢出，配乐署名是不是这一版真正用的曲子。
2. **字幕**：和配音逐句对；原声段中英字幕不重叠；翻译单复数、人称对。
3. **声音**：剪接点不切字（插原声处在静音中点）；纯配乐版验证停乐；ebur128 看响度和真峰值（见 `music.md`）。
4. **独立审片**（新题材或大改版时）：起一个没参与制作的子代理，给它联系表、字幕文件、时间线 json 和上面这份清单，让它逐项挑错。只开一个，用户对 token 敏感；小修改不用再送审。

## 交付

- 成片命名：`<片名>_修订v<n>_竖屏.mp4`（要横屏再加 `_横屏`），放 `$VL_OUT`，**不进仓库**。
- 渲染完立刻用 SendUserFile 发出（mp4 用 render 预览），说明这一版改了什么、片长、响度。
- 用户关浏览器也没关系：云端会话里后台任务会继续跑；如果用户说 token 不够、明天再看，就把这一版做完发出去，留一句“改了什么、下一步等你什么”。
- 用户提修改：只重渲改动的镜头 / 只重混音频（画面不动时只换音轨，几分钟出新版）。

## 视频号发布文案（用户说“定稿”后给）

模板 `assets/templates/视频号发布文案.md`，存成 `versions/v1/视频号发布文案.md` 并发给用户：
- 短标题 3 个（≤ 16 字，第一个是推荐），封面大字两行（和外框标题一致）。
- 描述正文 4 段：反差钩子 → 一句话概括全片 → 还没答案的问题 → 评论区提问；末尾带话题。
- 话题标签分“必带 / 推荐 / 可选”。
- 备注：敏感说法在文案里也保持限定词（“疑云”“有理由认为”，对方已否认）；新闻画面来源；配乐来源（Suno 要付费账号才能商用）。

## 收尾

- 代码、对齐 json、任务单、文案提交到 PR 分支（不提交配音和成片）。
- PR 留收尾留言、取消订阅、停后台监听（见 `grokbot-pr.md`）。
- 新曲子进曲库（`music.md`），这次学到的坑补进本 skill 的「踩过的坑」。
