# 导演简报与制作关卡（开做前先写这一页）

来源：@0xwhrrari《Motion Engineering: Build a Video Studio Around Opus 5.5》。核心：好片子靠的不是一句神奇提示词，而是模型外面那套系统。模型会用"最安全的默认值"填补没定的决定（居中大字 + 渐变背景 + 全部淡入 + 结尾 logo），所以开做前要把决定定下来。

## 1. 导演简报（每个项目一份 `brief.md`，用户确认后再做）

```
片子：<题目 / 产品>，<时长>，<画幅 9:16 / 16:9>，<平台>
观众只需要记住一件事：<一句话>
事实（不能编）：<真实产品界面、数据、品牌色、logo、歌词……从哪里来>
可以创作的：<镜头、转场、比喻、节奏>
参考（只借语法，不抄镜头）：<参考片 / 风格> → 先写成风格指南
不合格的标准：<比如：字看不清、出现假界面、像 PPT、开头 3 秒没有钩子>
交付：<有铺底版 / 仅音效版 / 横竖两版>
```

## 2. 参考 → 风格指南

用户给参考片时，先量（静止占比、切点、最快镜头、运动曲线、配色、字体），写成一页风格指南再动手，而不是拼贴参考里的镜头。

## 3. 状态表，而不是特效清单

"放大、变形、加粒子"描述的是动作，不是意义。每个节拍写：
- 进入时观众知道什么 → 离开时观众知道什么 → 这个节拍为什么存在；
- UI 类：先列状态（空 → 输入中 → 已提交 → 结果），再设计状态之间的连续变化。同一个组件可以变大小、颜色、内容、位置，但要始终"认得出是同一个东西"。

说不出第 4 个镜头为什么存在，它就不该进渲染。

## 4. 运动要有"重量"

每类物体一条运动规则：小控件可以干脆地弹，大面板要稳稳落定，镜头慢到不丢方向，标题快速进场然后停够时间让人读完。弹簧比通用缓动更自然，但**不要所有东西都弹**，全都回弹就没有精准感。每次运动后检查：观众知道下一眼该看哪里吗？

## 5. 声音在同一张时间表上

闭上眼只听声音：如果离开画面就没有形状，声音设计就没做完。

## 6. 先看帧，再导出

先出总览图（每个大节拍一帧 + 最快转场处的连续帧），给出具体批评再改。"文件生成了"不等于"片子成立"。

## 7. 横竖版本从源头做，不要裁

16:9 和 9:16 是两种构图：竖版字更大、同屏元素更少、镜头路线和故事更紧。共用素材、时间线和叙事状态，每个画幅单独定版式，单独出总览检查。

## 8. 把工作室存成文件，不是聊天记录

简报、风格指南、时间线、检查清单、交付结构都写成文件放进仓库。下一条片只换简报和素材。长任务从文件恢复进度，而不是靠聊天记忆。

## 9. 长任务设关卡，不放任

| 关卡 | 不满足就 |
|---|---|
| 简报确认 | 不开始制作 |
| 素材齐全（真实界面、角色图、歌） | **停下来问**，不要画一个以假乱真的替代品 |
| 风格总览图确认 | 不开始全片渲染 |
| 节拍截图确认 | 不开始高质量 / 长时间渲染 |
| 成片自查（规格、响度、字幕、事实） | 不交付 |

不可逆的品牌决定（logo、品牌色、口号）不替用户做。
