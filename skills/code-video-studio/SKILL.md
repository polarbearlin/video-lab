# 代码视频工作室

这个 skill 把一次完整的实战（《老板画饼》纸雕剧场 MV、《闻到煤气味》安全歌、《李白》水墨短片）沉淀成可复用的流程。核心思路：**每一帧都是时间 t 的纯函数**，网页里的 `renderAt(t)` 画出任意时刻，无头浏览器逐帧截图，ffmpeg 合成，音画共用同一张时间表。

完整代码仓库：`polarbearlin/video-lab`（私有）。参考源：https://github.com/Vincentwei1021/mg-styles-15

## 第 0 步：选题和文案优先（科普类）

文案和节奏是重中之重，表现形式其次。用户给题材时，先读 `references/topic-and-copy.md`：
- 用选题自检表筛（日常现象、一句话反常识问题、因果链 4 步以内、原理能画出来），给出 3–5 个改写好的"一句话问题"；
- 先交"文案与节奏表"（时间、时长、字幕、画面、节奏），确认后再做画面；
- 开头 3 秒第一帧完整、直接甩问题；字幕一换画面必须动；字幕停留按每秒 4–5 字；
- 让节奏本身讲道理（讲快就快、讲慢就慢、危险用重击、揭晓前停顿）；
- 先做 15–30 秒开头样片，满意再做整条。

## 第 0.2 步：每次调用，先给用户风格组合选择

用户提出主题后，**不要直接开做**。先读 `references/styles.md`，根据主题给出 3–4 个风格组合供选择，格式如下：

```
根据你的主题「<主题>」，推荐这几个方向：

A. <风格组合名>（主风格 + 点缀风格）
   为什么适合：<一句话，和主题/情绪/受众挂钩>
   画面会是：<一个最有代表性的镜头>
   制作量：<轻 / 中 / 重>，渲染时间约 <x>

B. ...
C. ...

我的倾向：<推荐哪个、为什么>。你选一个，或说想混搭哪两个。
```

挑组合时考虑：主题的情绪（温暖 / 严肃 / 搞笑 / 燃）、信息密度（数据多就要排版强的风格）、有没有歌（有节拍就选卡点感强的）、有没有真实素材（有就优先拼贴、纪实类）、渲染成本（3D 风格在无显卡环境很慢，要提前告知）。组合通常是"主风格 + 一处点缀"，比如"纸雕剧场主体 + 副歌用大字报砸字"。

同时确认这几件事（用户没说就按默认值，并在回复里写明）：
- 画幅：默认竖屏 1080×1920、30fps（抖音 / 视频号）
- 时长和范围：有歌就按歌词段落，用户常常只要"第一段"
- 音频：用户给的歌 / 旁白，还是由代码合成
- 角色：用代码画，还是用户提供形象图（见 `references/production.md` 的出图要求）

## 第 0.5 步：分镜表（带"承接"一列）

开做前写分镜表：时间、时长、画面、**承接物（谁活到下一拍）**、节奏类型（停 / 常 / 爆 / 击）。每个换场都要有一个东西留下来、变成下一个画面，镜头不切；镜头长度要有长有短，要有停顿和爆发。写不出承接物的地方就会像 PPT。规则和手法见 `references/one-take.md`。

## 第 1 步：先出截图，再做动画

用户明确要求过：**先出风格截图，确认了再做视频**（除非用户说"直接做"）。按歌词或文案的关键节点出 5–8 张关键帧，横向拼成一张总览图发给用户。截图阶段就把明显问题修掉：字被裁、元素重叠、人物出框、字体缺字成方块。

## 第 2 步：音频和时间轴

有歌时，先把歌词逐字对齐到时间，后面所有画面动作都卡在这些时间上。用 `scripts/align_lyrics.py`（人声分离 + 中文识别 + 拼音对齐），细节见 `references/audio-lyrics.md`。对齐后核对两件事并告诉用户：实际唱的和歌词文本有没有出入（字幕以用户的歌词为准）；歌词里有没有事实错误（画面上的事实卡写准确说法）。

## 第 3 步：制作

- 选纸雕微缩剧场：读 `references/paper-diorama.md`，以 `assets/example-paper-diorama.js` 为骨架改。
- 选其他风格：按 `references/styles.md` 里该风格的技术路线写。2D 风格用 SVG 字符串每帧重建最简单；3D 用 Three.js。
- 所有随机数用固定种子；不要用真实时钟或 CSS 过渡；图片在 `renderAt` 里等加载完再截图。
- 字幕：逐字按唱到的时间浮现，带底板，长句自动折两行。左上角放栏目角标（全局图层，不参与转场）。

## 第 4 步：渲染

- 渲染器：`harness/render.mjs`（来自 mg-styles-15）。2D 页面 0.1–0.3 秒/帧；Three.js 在无显卡的云端约 2 秒/帧。
- **超过 20 秒就分段渲染**：每段 12 秒，单独启动浏览器，失败自动重试，已完成的段跳过（`scripts/render_segments.sh`）。云端容器可能重启，分段能保住进度。
- 3 个渲染进程即可（4 核机器），别开太多。渲染本身不消耗 token，用后台任务 + 完成通知，别轮询。
- 快速运动多的片子加运动模糊：`--mb 6 --shutter 0.5`（2D 页面可以全程开；Three.js 太慢，只在终版或快速段落开）。
- 拼接后混音：歌曲原样 + 音效轨低 3–6dB，`alimiter` 限幅，响度对齐原曲（约 -14 LUFS）。

音效：合成拟音要有材质（玻璃、木头、空气、低频重击、气泡），并且全部送进同一份混响，见 `references/one-take.md` 第 5 节和 `assets/example-onetake-score.py`。

## 第 5 步：检查、评审、交付

- 抽帧拼总览图自查（每 2 秒一帧），再看转场处的连续帧。逐个换场检查：有没有东西承接过去？有没有完全静止的停顿？镜头长度是不是太平均？
- 用户要高标准时，用独立子代理按 `references/production.md` 里的评审提示词打分，**最多改 3 轮**（用户对 token 敏感）。
- 交付：科普类同时导出"有铺底版"和"仅音效版"（发布时在平台曲库配热门歌，别把热门歌合成进视频）。原画质文件用下载卡片发；再做一个在线放映页（Artifact，单个视频压到 15MB 以内）方便对比。说明清楚这一版的不足。
- 提醒用户把代码推到 GitHub（只推代码和素材，不推视频、字体、采样库）。

## 和用户沟通的习惯

用户是中文自媒体创作者，不写代码。回复用中文、说人话：说清楚做了什么、现在到哪一步、还要多久、哪里不满意。长任务给出预计时间，完成后自动通知，不要让用户反复来问。涉及云端环境（网络、密钥、GitHub 授权）的问题，给可以直接复制粘贴的步骤。
